# IEEE ICA 2026 発表シナリオ案とダッシュボード設計

状態: 第 2 案（2026-11-15）
対象論文: *Grant Once, Revoke Everywhere: Cross-Application AI Agent Authorization via On-Chain Credentials*

第 1 案からの変更点は 3 つです。

- コンセプト動画を約 6 分に収めるため、登場人物を社員 1 人、エージェント 1 体、発行者 2 者に絞りました。
- 題名にある「クロスアプリケーション」を動画の中心に置きました。1 枚のトークンが 4 つのアプリケーションで通用し、1 回の取消で 4 つ同時に閉じます。
- 発行者を 5 種類並べた第 1 案の世界は、任意で使える予備の画面として残しました（6 節）。

## 1. 発表全体の時間配分

発表 15 分、質疑 5 分を想定しています。

|---|---|---|---|
| 1 | 2:00 | 背景の説明（別途用意） | 口頭 |
| 2 | 6:00 | コンセプト動画（この文書の対象） | 動画 |

口頭で話す部分（1、3、4）の原稿は `docs/ICA2026_TALK_SCRIPT.md`、スライドは `docs/ica2026-talk/index.html` にあります。

動画の例は、論文の事例研究（5 章 E 節）と同じ構成にしてあります。エージェントが 1 つの仕事で、ファイル用の MCP サーバー、メモリ用の MCP サーバー、Web API、スマートコントラクトの 4 つを通ります。動画のあとの実験説明では「いま見た場面を 75 回試した」とそのまま続けられます。

## 2. コンセプト動画で伝えること

一文で言うと、次のとおりです。

> AI エージェントの権限を、誰が発行したかが見えて、期限を付けられて、発行者がいつでも燃やせるトークンにする。一度与えれば複数のアプリケーションで通用し、一度取り消せばそのすべてで消える。

聴衆に持ち帰ってほしいのは 3 点です。

1. **権限は見える。** エージェントが何をしてよいかは、その財布にあるトークン（NFT）そのものです。人間の権限も同じくトークンです。
2. **一度の付与が複数のアプリケーションで通用する。** アプリケーションは名簿を持たず、「どのトークンで開くか」だけを決めます。
3. **一度の取消がすべてに効く。** 発行者がトークンを燃やすと、すべてのアプリケーションで同時に権限が消えます。期限付きのトークンは、何もしなくても切れます。

論文の導入にある 3 つの問いを、動画の最初と最後に置きます。

- このエージェントは何をしてよいのか（What may this agent do?）
- いつまでか（Until when?）
- 今すぐ止めるにはどうするか（How do I stop it — now?）

## 3. 登場人物とトークン

| 登場人物 | 役 | 画面での見え方 |
|---|---|---|
| **Mika Sato** | Acme Corp のソフトウェアエンジニア。人間の本人（principal） | 丸い人物アイコン。画面上段の「You」 |
| **Kit** | Mika のコーディングエージェント | 四角いロボットのアイコン。画面下段 |
| **Acme Corp** | 雇用主 | 建物のアイコン、紫 |

トークンは 3 枚だけです。

| トークン | 発行者 | 持ち主 | 通用する先 | 期限 |
|---|---|---|---|---|
| Employee ID | Acme Corp（雇用主） | Mika | Summary API、委任トークンの発行 | なし |
| Release assistant | **Mika（本人）** | Kit | 下の 4 つのアプリケーション | なし |
| Production access · 30 min | **Acme Corp（雇用主）** | Kit | Deploy pipeline | 30 分 |

「Release assistant」が通用する 4 つのアプリケーションが、クロスアプリケーションの例です。

| アプリケーション | 種類 | Kit がすること | 論文の事例研究での対応 |
|---|---|---|---|
| Project files | MCP サーバー | プロジェクトを読む | filesystem MCP サーバー |
| Agent memory | MCP サーバー | 要点を記憶する | memory MCP サーバー |
| Summary API | Web API | 変更履歴を要約する | Web アプリケーション |
| Release registry | スマートコントラクト | 要約のハッシュを記録する | コントラクト |

論文の用語との対応は次のとおりです。

- **委任トークン（delegation token）:** Mika が Kit に発行する「Release assistant」。燃やせるのは Mika だけで、これが「止めるスイッチ」です。
- **資格トークン（qualification token）:** 雇用主が発行する「Employee ID」と「Production access」。発行者が違っても、同じ財布に並びます。
- **入れ子:** Mika が委任トークンを発行できるのは、Employee ID を持っているからです。発行する権利そのものをトークンで決めるのが、TCTC（Token-Controlled Token Circulation）の名前の由来です。

## 5. ダッシュボードの場面

`?story=ica2026` で開くと、次の 7 場面をサンプルデータで順に再生します。

| 場面 | 題 | 画面に映るもの |
|---|---|---|
| 1 | Mika and her agent | 上段に Mika の「Employee ID」（発行者: 雇用主）。下段の Kit は「no permissions」 |
| 2 | Grant once | Kit に「Release assistant」（発行者: You）が現れる。4 行に MCP server、MCP server、Web API、Smart contract と並ぶ。Kit の状態が 4 秒ごとに次のアプリケーションへ進む |
| 3 | Another issuer, a time limit | Kit に「Production access · 30 min」（発行者: 雇用主）が加わり、残り時間が減っていく |
| 4 | Time runs out | 6 秒のカウントダウンのあと、カードに「EXPIRED」の印が付く。取引は発生しない。Kit の状態が「Denied」になる |
| 5 | Something goes wrong | Kit の状態が警告に変わる |
| 6 | One burn, every door | 「Release assistant」に「BURNED」の印が付き、4 行すべてに取り消し線が入る。Kit は「Denied at every door」 |
| 7 | On one screen | 最終状態 |

操作は次のとおりです。

- **場面の移動:** 右矢印で次へ、左矢印で前へ進みます。
- **説明バー:** `h` キーで隠せます。撮影時は隠す想定です。
- **途中から始める:** URL に `&scene=3` のように付けます。
- **色のテーマ:** URL に `&theme=light` または `&theme=dark` を付けます。
- **取消の操作:** 「Revoke」ボタンは実際に押せます。場面 6 を待たずに、押して燃やすところを撮ることもできます。
- **燃えたカード:** 20 秒間画面に残ります。

画面右上には常に「Story mode · sample data」と表示します。

### Sepolia の実データで撮る

同じ 7 場面を、サンプルデータではなく Sepolia の実データで表示できます。URL に `&live` を付けます。

```
http://localhost:5173/?story=ica2026&live
```

この表示では、トークン、発行者、期限、通用する先を 12 秒ごとに Sepolia から読みます。台本から出すのは、下の説明文とエージェントの作業状況の 1 行だけです。画面右上には「Live on Sepolia · status lines scripted」と表示します。

登場人物の実体は次のとおりです。配置先のアドレスは `demo/ica2026/deployment.sepolia.json` にあります。

| 役 | Sepolia 上の実体 |
|---|---|
| Acme Corp | これまでのデモと同じ発行用アカウント |
| Mika | このデモ用に作ったアカウント。鍵は `demo/ica2026/.env.local` |
| Kit | エージェント用に作ったアカウント。鍵は `demo/ica2026/kit/.env.local` |
| トークン 3 種 | Acme Staff Credentials、Mika's Delegations、Acme Production Passes |
| アプリケーション 5 つ | それぞれ「どのトークンで開くか」だけを宣言する小さなコントラクト |

「Mika's Delegations」は、Employee ID を持っていないと発行できません。Mika 自身の NFT が、エージェントに権限を与える根拠になっています。

場面は、リポジトリの直下で次のコマンドを実行して進めます。1 回のコマンドが 1 件の取引です。

| 場面 | コマンド | Sepolia で起きること |
|---|---|---|
| 1 | `node demo/ica2026/demo.mjs reset` | Kit が何も持たない状態に戻す |
| 2 | `node demo/ica2026/demo.mjs grant` | Mika が「Release assistant」を Kit に発行する |
| 3 | `node demo/ica2026/demo.mjs pass` | Acme が 30 分の「Production access」を Kit に発行する |
| 4 | `node demo/ica2026/demo.mjs expire 60` | その期限を 60 秒後に縮める。あとは何もしなくても切れる |
| 6 | `node demo/ica2026/demo.mjs burn` | Mika が「Release assistant」を燃やす |

撮影時の注意は次のとおりです。

- **反映までの時間:** 取引が取り込まれるまで 12〜30 秒、画面の読み直しが 12 秒ごとなので、コマンドを実行してからカードが変わるまで最大 40 秒ほどかかります。
- **場面 5 と 7:** チェーン上では何も起きません。ダッシュボードで右矢印を押して説明文だけ進めます。
- **場面 4 の「Denied」:** 台本の秒数ではなく、Sepolia で実際に期限が切れた時点で表示されます。
- **`expire` の秒数:** 45 秒以上にしてください。取引が取り込まれた時点で期限が過ぎていると拒否されます。
- **「Revoke」ボタン:** ウォレットを接続していないと表示されません。画面のボタンで燃やす場面を撮る場合は、Mika の鍵をブラウザのウォレットに入れて接続します。
- **現在の状態の確認:** `node demo/ica2026/demo.mjs status` で、誰が何を持っているかを表示します。

## 6. 予備: 発行者の多い画面

`?story=ica2026-wide` は第 1 案の世界です。経理担当の Aya Tanaka と 4 体のエージェントが、雇用主、行政、上司、本人、別のエージェントという 5 種類の発行者のトークンを持ちます。

6 分の中で順に語るには重いので、動画の 5:10–5:40「発行者は誰でもよい」で 1 枚の絵として使う想定です。`?story=ica2026-wide&scene=4` で、5 種類の発行者がすべて並んだ状態になります。登場人物の設定が本編（エンジニアとコーディングエージェント）と違うため、使う場合は「別の職場でも同じ」という見せ方になります。

## 7. ダッシュボードの設計

### 原則

1. **主役はトークン。** 最初の画面（Overview）には、人とトークンだけを置きます。アドレスの入力欄、対象コントラクトの調査、コレクションの発行などは「Manage」画面にあります。
2. **人間とエージェントを取り違えない。** 形、位置、ラベルの 3 つで区別します。
3. **発行者が一目で分かる。** すべてのトークンに発行者のアイコン、名前、種類の色を付けます。
4. **本物の画面である。** シナリオ再生と実データは同じ画面部品を使います。違うのはデータの出どころだけです。

### 人間とエージェントの区別

| | 人間（You） | エージェント |
|---|---|---|
| 位置 | 画面上段の横長の帯 | 下段 |
| アイコン | 丸い人物アイコン | 角の丸い四角のロボット。アドレスから自動生成し、Manage 画面で画像に差し替えられる |
| トークンの形 | 横長の「証明書」。左に発行者の印 | 縦長の「通行証」。上に穴と発行者色の帯 |
| ラベル | "You · human principal" | "Your agents · AI" |

エージェントが 1 体だけのときは、トークンのカードを大きく表示します。

### 発行者の種類

| 種類 | 色 | アイコン | 決め方 |
|---|---|---|---|
| You（本人） | 青 | 人物 | コレクションの owner が、接続中の財布と同じ |
| AI agent | ピンク | ロボット | owner が、登録済みのエージェントのアドレスと同じ |
| Employer | 紫 | 建物 | Manage 画面で付けた名前と種類 |
| Government | 緑 | 庁舎 | 同上 |
| Manager | 黄 | かばん | 同上 |
| Organization / 未設定 | 灰 | 六角形 | 名前がなければアドレスの短縮表示 |

発行者の名前と種類、トークンの題名は、チェーン上にはありません。連絡先のように、このブラウザに保存するラベルとして扱います。

### カードに載せる情報

- 題名（例: Release assistant）。ラベルがなければコレクション名と番号
- 発行者（アイコン、名前、種類）。本人が発行したものは "you" と表示
- 通用する先。シナリオ再生ではアプリケーションの種類（MCP server、Web API、Smart contract）を、実データでは役割名（例: MINTER_ROLE）を右側に表示
- 残り時間。期限なしなら "no expiry"
- 取消ボタン。発行者本人のときだけ表示
- 状態の変化: 発行（光って現れる）、取消（「BURNED」の印）、期限切れ（「EXPIRED」の印と "no transaction"）

### シナリオ再生と実データの違い

| | シナリオ再生（`?story=ica2026`） | ライブ（`&live` を追加） | 通常の画面 |
|---|---|---|---|
| トークンと発行者 | サンプル | Sepolia から読む | 選んだチェーンから読む |
| 「You」 | Mika | Mika の実アカウント | 接続した財布 |
| 名前、アイコン、アプリケーションの種類 | 台本のラベル | 台本のラベル | Manage 画面で付けたラベル |
| 説明文とエージェントの作業状況 | 台本 | 台本 | なし |
| 画面右上の表示 | Story mode · sample data | Live on Sepolia · status lines scripted | なし |

MCP サーバーや Web API は、それ自体はコントラクトではありません。そこで各アプリケーションは、どのトークンで開くかを宣言するだけの小さなコントラクトをチェーン上に持ちます。アプリケーションの入口はそのコントラクトに問い合わせ、ダッシュボードも同じものを読みます。「MCP server」「Web API」という種類の表示はチェーン上にはなく、ラベルとして付けています。

エージェントの作業状況（緑や赤の 1 行）は、どの表示でも台本から出しています。チェーンからは分からない情報です。

## 8. 決まったこと（2026-11-15）

1. **設定。** ソフトウェアエンジニアの Mika とコーディングエージェントの Kit で進めます。名前や職種は `dashboard/src/lib/story.ts` の 1 か所で変えられます。
2. **「発行者は誰でもよい」の 30 秒。** 動画に入れます。
